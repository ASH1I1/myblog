## 一、产品概述

### 1.1 项目名称

- **产品名称**：NewBlog 个人博客系统
- **项目仓库**：newblog
- **一句话描述**：一个面向个人博主的博客网站，由「用户端展示门户」和「博主管理后台」两个端组成，博主可在后台完成文章的撰写、发布与管理，访客可浏览文章并了解博主。

### 1.2 项目目标

| 编号 | 目标 | 可衡量标准 |
| --- | --- | --- |
| G1 | 访客能流畅地浏览博客文章 | 用户端 3 个页面（首页 / 文章详情 / 关于我）全部可用且可互相跳转 |
| G2 | 博主无需接触代码或数据库即可管理文章 | 后台登录 + 仪表盘 + 文章增删改查全流程可用 |
| G3 | 全站适配多端访问 | 桌面、平板、手机三档设备下页面均可用、无横向滚动、无内容溢出 |
| G4 | 基础安全可控 | 后台必须登录后才能访问；密码不以明文存储 |

### 1.3 核心价值

1. **对博主（写作者）**
   - 极简的写作闭环：登录 → 新建文章 → 保存草稿 → 发布 → 在仪表盘查看文章数据。
   - 零运维负担：一个后台搞定所有内容管理，不需要手动改文件、跑脚本。
2. **对访客（读者）**
   - 干净、专注的阅读体验：无广告、无干扰，突出正文内容本身。
   - 快速找到内容：首页按时间倒序展示文章列表，点击即读。
3. **对系统本身**
   - 结构清晰、职责分离：用户端（只读）与管理后台（读写）解耦，便于后续扩展（如评论、标签、搜索等）。

### 1.4 本期范围（Scope）

**本期实现（In Scope）：**

- 用户端：首页、文章详情页、关于我页面（含全局导航与页脚）。
- 管理后台：管理员登录、后台仪表盘（文章统计）、文章管理（列表 / 新建 / 编辑 / 删除）。
- 全站响应式设计。

**本期不做（Out of Scope，留待后续迭代）：**

- 用户注册、多用户、评论、点赞、收藏。
- 站内搜索、标签页 / 分类页、RSS 订阅。
- 图片上传服务、第三方登录、文章定时发布。

## 二、目标用户

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 | 使用场景 | 使用频率 |
| --- | --- | --- | --- | --- |
| **访客（读者）** | 通过链接或搜索引擎进入博客的普通用户，无需登录 | 快速找到感兴趣的文章；阅读时排版舒适；了解博主是谁 | 在手机 / 电脑上浏览首页文章列表，点开某篇文章阅读，或访问「关于我」了解博主 | 低频、随机进入 |
| **博主（管理员）** | 博客的唯一所有者与内容管理者，需登录 | 高效地写文章、改文章、删文章；一眼看清博客数据概况 | 登录后台 → 写新文章 / 修改旧文章 → 查看仪表盘上的文章统计 | 高频、周期性写作 |

### 2.2 典型使用场景

1. **访客阅读**：访客打开首页 → 浏览文章卡片列表 → 点击某个标题 → 进入文章详情页阅读 → 通过底部「上一篇 / 下一篇」继续阅读。
2. **博主打理博客**：博主打开后台登录页 → 输入账号密码 → 进入仪表盘查看文章统计 → 进入文章管理列表 → 新建并发布一篇文章 → 返回列表确认状态为「已发布」。
3. **博主修改疏漏**：博主发现旧文有错别字 → 登录后台 → 在列表中搜索到该文章 → 编辑并保存 → 用户端立即看到更新。

### 2.3 用户设备假设

- 访客：移动端浏览占比预计 ≥ 50%（手机为主，桌面为辅）。
- 博主：以桌面端管理为主，但后台在手机上也要能完成基本操作（查看、编辑非长篇内容）。

## 三、功能需求

### 3.1 功能结构与页面地图

```
个人博客系统
├── 用户端（访客，无需登录）
│   ├── 首页                /
│   ├── 文章详情页          /posts/:id
│   └── 关于我页面          /about
│
└── 博主管理后台（需登录）
    ├── 管理员登录          /admin/login
    ├── 后台仪表盘          /admin            （文章统计）
    └── 文章管理            /admin/posts      （列表 / 新建 / 编辑 / 删除）
        ├── 新建文章        /admin/posts/new
        └── 编辑文章        /admin/posts/:id/edit
```

**全局约定：**

- 用户端所有页面共享同一套顶部导航栏和页脚。
- 后台所有页面（除登录页外）共享同一套后台布局（侧边栏 + 内容区），且必须登录后才能访问。
- 用户端访问不存在的内容时，展示 404 页面，并提供「返回首页」入口。

---

### 3.2 用户端

#### 3.2.1 首页（`/`）

**功能描述**

- 展示博客的文章列表，作为访客进入网站的第一落点。
- 文章按发布时间**倒序**排列（最新在前），仅展示「已发布」状态的文章，草稿不可见。
- 支持分页浏览（每页 9 篇，可配置）。
- 点击任意文章卡片进入文章详情页。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `Navbar` 顶部导航 | 站点名称 / Logo + 导航链接（首页、关于我） | 当前所在页面的导航项高亮；移动端折叠为汉堡菜单 |
| `Hero` 博主简介区（可选，推荐） | 博主头像 + 一句话自我介绍 | 内容可写死或来自配置；移动端纵向排列 |
| `PostCard` 文章卡片 | 封面图（可选）、标题、摘要、发布日期、阅读量 | 整卡可点击跳转详情页；无封面图时展示占位样式；摘要为空时自动截取正文前 100 字 |
| `PostList` 文章列表 | 响应式网格排列 `PostCard` | 桌面 3 列 / 平板 2 列 / 移动 1 列 |
| `Pagination` 分页器 | 上一页 / 页码 / 下一页 | 当前页高亮；首页禁用「上一页」；仅 1 页时隐藏分页器 |
| `Footer` 页脚 | 版权信息（© 年份 + 站点名）、社交链接（可选）、备案号（可选） | 年份自动取当前年份 |

**页面状态**

- **加载中**：展示骨架屏或加载指示器。
- **空状态**：当没有任何已发布文章时，展示「暂无文章，敬请期待」文案，不展示分页器。
- **错误状态**：数据获取失败时展示错误提示与「重试」按钮。

**验收标准**

- [ ] 首页按发布时间倒序展示所有已发布文章，草稿文章不出现。
- [ ] 点击任意文章卡片正确跳转至对应文章详情页。
- [ ] 分页功能正常，页码切换后列表内容正确变化。
- [ ] 无文章、加载失败时分别有明确的状态提示。

---

#### 3.2.2 文章详情页（`/posts/:id`）

**功能描述**

- 展示单篇文章的完整内容，是访客阅读的核心页面。
- 正文支持 Markdown 渲染（标题、列表、引用、代码块、图片、链接等），代码块需有高亮与等宽字体。
- 提供「上一篇 / 下一篇」导航，便于连续阅读。
- 访问不存在或未发布的文章时，展示 404 页面。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `Navbar` 顶部导航 | 同首页，全局复用 | 同上 |
| `ArticleHeader` 文章头部 | 文章标题（H1）、发布日期、阅读量、作者（可选） | 标题字号明显大于正文，移动端自动换行不溢出 |
| `MarkdownRenderer` 正文渲染区 | 渲染 Markdown 正文 | 正文最大宽度约 720px 居中（保证阅读舒适度）；图片自适应宽度不溢出；代码块超长时横向滚动，不撑破布局 |
| `PrevNextNav` 上下篇导航 | 「上一篇：xxx」「下一篇：xxx」链接 | 无上一篇 / 下一篇时该侧隐藏或置灰 |
| `Footer` 页脚 | 全局复用 | 同上 |

**页面状态**

- **加载中**：正文区展示骨架屏。
- **文章不存在 / 未发布**：展示 404 提示 +「返回首页」按钮。
- **错误状态**：加载失败展示错误提示与「重试」按钮。

**验收标准**

- [ ] 文章标题、日期、正文内容与后台数据一致。
- [ ] Markdown 中标题、列表、代码块、图片、链接均正确渲染。
- [ ] 长代码块、宽图片在移动端不会造成页面横向滚动。
- [ ] 上一篇 / 下一篇链接正确，边界情况（首篇 / 末篇）处理正确。
- [ ] 访问不存在或未发布的文章时展示 404 页面。

#### 3.2.3 关于我页面（`/about`）

**功能描述**

- 介绍博主本人：个人简介、技能 / 经历（可选）、联系方式。
- 内容为静态展示页，可由配置或简单数据结构驱动，无需后台编辑（本期）。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `Navbar` 顶部导航 | 全局复用 | 「关于我」导航项高亮 |
| `ProfileCard` 个人资料卡 | 头像、昵称、一句话签名 | 移动端居中展示 |
| `BioSection` 个人简介 | 多段文字介绍博主 | 支持基础富文本 / Markdown 渲染 |
| `SkillTimeline` 技能 / 经历时间线（可选） | 时间 + 事件 / 技能条目 | 桌面双栏、移动端单栏 |
| `ContactList` 联系方式 | 邮箱、GitHub、社交平台等链接列表 | 链接支持点击跳转，外链新窗口打开 |
| `Footer` 页脚 | 全局复用 | 同上 |

**验收标准**

- [ ] 页面内容结构清晰，包含简介与联系方式。
- [ ] 所有外链可点击且能正常打开。
- [ ] 移动端无布局错乱或内容溢出。

### 3.3 博主管理后台

#### 3.3.1 管理员登录（`/admin/login`）

**功能描述**

- 博主通过账号 + 密码登录后台，登录成功后方可访问后台其余页面。
- 系统只有一个管理员账号（博主本人），账号信息由系统初始化配置（数据库或配置文件），**密码必须加密存储（如 bcrypt），禁止明文**。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `LoginForm` 登录表单 | 账号输入框、密码输入框（密文显示）、登录按钮 | 两项均必填；提交时按钮进入 loading 并禁用防重复提交 |
| `ErrorMessage` 错误提示 | 展示登录失败信息 | 统一提示「账号或密码错误」，不提示具体哪一项错 |
| （可选）记住我 / 登出 | 会话保持与退出 | 详见下方会话规则 |

**交互与规则**

1. 登录成功后跳转到后台仪表盘（`/admin`）。
2. 未登录状态访问任意后台页面时，自动重定向到登录页；登录成功后跳回原目标页面（可选）。
3. 登录失败时清空密码框、保留账号，聚焦密码框。
4. 会话有效期建议 7 天；后台布局中提供「退出登录」按钮，退出后清除会话并回到登录页。
5. （可选，推荐）同一账号连续 5 次登录失败后，锁定 10 分钟。

**验收标准**

- [ ] 正确账号密码可登录并跳转仪表盘。
- [ ] 错误账号或密码登录失败，有明确错误提示，且不泄露具体错误项。
- [ ] 未登录访问后台任意页面均被重定向到登录页。
- [ ] 退出登录后无法再直接访问后台页面。
- [ ] 密码在存储中为加密值，非明文。

#### 3.3.2 后台仪表盘（`/admin`）

**功能描述**

- 博主登录后的默认落地页，用于一屏掌握博客的文章数据概况。
- 展示核心统计指标与最近文章动态，帮助博主快速定位到需要处理的文章。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `AdminLayout` 后台布局 | 侧边栏（仪表盘、文章管理、退出登录）+ 顶部栏 + 内容区 | 侧边栏当前菜单项高亮；移动端折叠为抽屉 / 顶部菜单 |
| `StatCard` 统计卡片组 | 文章总数、已发布数、草稿数、（可选）总阅读量 | 数据实时来自文章数据；数字变化时保持卡片布局稳定 |
| `RecentPostsTable` 最近文章列表 | 最近 5 篇更新 / 发布的文章（标题、状态、更新时间） | 点击某行跳转到对应编辑页 |
| `QuickAction` 快捷入口（可选，推荐） | 「新建文章」按钮 | 点击跳转 `/admin/posts/new` |

**统计口径**

- **文章总数** = 所有状态文章之和。
- **已发布** = 状态为「已发布」的文章数。
- **草稿** = 状态为「草稿」的文章数。
- （可选）**总阅读量** = 所有文章阅读量之和。

**页面状态**

- **加载中**：统计卡片与列表展示骨架屏。
- **空状态**：无文章时统计为 0，最近文章列表展示「暂无文章，去写第一篇吧」+ 新建入口。

**验收标准**

- [ ] 三个核心统计数字与实际文章数据一致，新增 / 删除 / 发布文章后刷新能正确变化。
- [ ] 最近文章列表展示正确，点击可进入对应编辑页。
- [ ] 后台侧边栏导航各入口跳转正确，当前页高亮。

#### 3.3.3 文章管理

##### A. 文章列表（`/admin/posts`）

**功能描述**

- 以表格形式展示全部文章（含草稿与已发布），支持搜索、筛选与分页。
- 每行提供「编辑」「删除」操作，页面顶部提供「新建文章」入口。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `PostTable` 文章表格 | 列：标题、状态（已发布 / 草稿）、发布时间、更新时间、操作 | 标题列可点击进入编辑页；状态用不同颜色标签区分 |
| `PostFilterBar` 筛选栏 | 搜索框（按标题搜索，输入防抖）+ 状态筛选（全部 / 已发布 / 草稿） | 筛选条件变化后立即刷新列表；可一键清空筛选 |
| `Pagination` 分页器 | 每页 10 条 | 同用户端分页规则 |
| `ConfirmDialog` 删除确认弹窗 | 二次确认删除 | 弹窗展示文章标题，明确「删除后不可恢复」；确认按钮为危险色 |
| `EmptyState` 空状态 | 无文章 / 无搜索结果 | 无文章时引导新建；无搜索结果时提示「未找到匹配文章」 |

**验收标准**

- [ ] 列表正确展示全部文章（含草稿），默认按更新时间倒序。
- [ ] 搜索、状态筛选、分页可组合使用且结果正确。
- [ ] 点击「删除」弹出确认框，确认后文章被删除且列表立即刷新；取消则不删除。
- [ ] 点击「编辑」进入对应文章的编辑页。

##### B. 新建 / 编辑文章（`/admin/posts/new`、`/admin/posts/:id/edit`）

**功能描述**

- 提供表单供博主撰写与修改文章，支持保存为草稿或直接发布。
- 新建与编辑复用同一表单组件；编辑时表单需回填已有数据。

**页面组件**

| 组件 | 说明 | 关键交互 / 规则 |
| --- | --- | --- |
| `PostForm` 文章表单 | 字段：标题（必填）、摘要（可选）、正文（必填，Markdown）、封面图 URL（可选）、状态（草稿 / 已发布） | 详见下方字段规则 |
| `MarkdownEditor` Markdown 编辑器 | 正文编辑区，支持 Markdown 语法 | 推荐提供「编辑 / 预览」双栏切换（移动端为 Tab 切换） |
| `FormActions` 操作区 | 「保存草稿」「发布 / 更新」按钮 | 保存时按钮 loading；成功后提示并跳转到文章列表 |
| `UnsavedGuard` 离开提醒（可选，推荐） | 有未保存修改时离开页面提醒 | 防止误触丢失内容 |

**字段规则**

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| 标题 | 文本 | 是 | 长度 ≤ 100 字 |
| 摘要 | 多行文本 | 否 | 长度 ≤ 200 字；留空时前台自动截取正文前 100 字 |
| 正文 | Markdown | 是 | 无长度硬限制（建议 ≤ 5 万字） |
| 封面图 | URL | 否 | 本期仅支持填写图片链接，不做上传 |
| 状态 | 枚举 | 是 | 「草稿」/「已发布」，默认「草稿」 |
| 发布时间 | 时间 | — | 状态切换为「已发布」时自动记录发布时间 |

**交互规则**

1. 新建成功后：跳转到文章列表，并提示「保存成功」。
2. 编辑页需能通过 URL 直接访问（收藏 / 刷新不丢失），文章 ID 不存在时展示错误提示与返回入口。
3. 表单校验失败时，在对应字段下方展示错误文案，且阻止提交。

**验收标准**

- [ ] 新建文章：填写标题与正文后可保存为草稿；表单校验（标题、正文必填）生效。
- [ ] 发布文章：状态设为「已发布」保存后，用户端首页与详情页立即可见。
- [ ] 编辑文章：回填数据正确，修改保存后用户端同步更新。
- [ ] 草稿文章在用户端任何位置均不可见。
- [ ] 删除文章后，用户端对应详情页返回 404。

## 四、非功能性需求

### 4.1 响应式设计（核心需求）

**断点定义**

| 档位 | 断点范围 | 目标设备 |
| --- | --- | --- |
| 移动端 | < 768px | 手机（含竖屏 / 横屏） |
| 平板 | 768px – 1023px | 平板、小尺寸笔记本 |
| 桌面端 | ≥ 1024px | 常规桌面显示器 |

- 内容区最大宽度 **1200px**，居中展示；超出部分留白。
- 页面容器左右内边距：移动端 16px，平板及以上 24px。
- 采用移动优先（Mobile First）策略开发，由小到大逐档适配。

**全局响应式规则**

- 顶部导航栏在 < 768px 折叠为汉堡菜单，展开后为全屏或下拉菜单。
- 所有图片 `max-width: 100%`，不溢出容器。
- 所有可点击元素触控目标 ≥ 44×44px（移动端）。
- 任何页面在任何宽度下 **不得出现横向滚动条**（长代码块、表格等局部区域允许容器内横向滚动）。
- 字号不随视口宽度无限缩放；移动端正文最小字号不低于 15px。

**逐页面响应式要求**

| 页面 / 区域 | 桌面端（≥1024px） | 平板（768–1023px） | 移动端（<768px） |
| --- | --- | --- | --- |
| 首页文章列表 | 3 列卡片网格 | 2 列卡片网格 | 单列卡片，整宽 |
| 首页 Hero 区 | 头像居左 / 文字居右 | 同桌面缩放 | 纵向居中排列 |
| 文章详情正文 | 最大宽度 720px 居中，字号 17–18px | 同桌面 | 字号 16px，左右 16px 内边距 |
| 代码块 / 预格式化文本 | 容器内横向滚动 | 同桌面 | 同桌面（不撑破页面） |
| 关于我 | 简介 + 时间线双栏 | 双栏压缩 | 全部单栏纵向排列 |
| 登录页 | 表单卡片居中（宽约 400px） | 同桌面 | 卡片占满宽度（保留 16px 边距） |
| 后台布局 | 左侧固定侧边栏（约 240px）+ 内容区 | 侧边栏收起为图标栏 | 侧边栏隐藏，汉堡菜单唤起抽屉 |
| 仪表盘统计卡片 | 一行 4 个 | 一行 2 个 | 一行 1–2 个 |
| 文章管理表格 | 完整表格 | 完整表格 | 表格横向滚动，或降级为卡片式列表 |
| 文章编辑页 | 编辑器 + 预览双栏 | 双栏压缩 | 「编辑 / 预览」Tab 切换 |

**验收标准**

- [ ] 在 375px（手机）、768px（平板）、1440px（桌面）三种宽度下逐页检查，均无横向滚动、无内容溢出、无重叠。
- [ ] 导航栏、后台侧边栏在移动端可正常展开 / 收起，且不影响内容操作。
- [ ] 所有页面关键操作（阅读、登录、增删改查）在移动端可完整完成。

### 4.2 兼容性

- 支持主流现代浏览器最近两个大版本：Chrome、Edge、Firefox、Safari（含 iOS Safari）。
- 不要求兼容 IE 及已停止维护的浏览器。

### 4.3 性能

- 首页首次内容渲染（FCP）在正常网络下 ≤ 2s（本地开发环境 ≤ 1s）。
- 文章列表分页加载，避免一次性渲染全部文章。
- 图片建议懒加载；静态资源启用压缩。

### 4.4 可访问性与 SEO

- 语义化 HTML：合理使用 `header` / `nav` / `main` / `article` / `footer` 等标签；文章详情页标题使用 `h1` 且每页唯一。
- 所有图片提供 `alt` 文本；表单控件提供 `label`。
- 文章详情页设置独立 `title` 与 `meta description`（取文章摘要），利于搜索引擎收录。
- 页面颜色对比度满足 WCAG AA 基本要求。

### 4.5 安全

- 管理员密码必须加密存储（bcrypt / argon2 等），禁止明文或可逆加密。
- 所有后台接口（读与写）必须在服务端校验登录态，不能仅依赖前端路由守卫。
- 富文本 / Markdown 渲染须做 XSS 防护（如渲染前对 HTML 转义或使用白名单过滤）。
- 登录接口做基础防暴力破解（失败次数限制或延迟响应）。
- 用户输入（标题、摘要、正文等）在服务端做长度与类型校验。

## 五、技术实现建议（非强制）

> 若仓库中已有技术栈约定，以仓库约定为准；否则可参考以下建议。

- **前端**：React / Vue 均可；用户端与后台共用同一应用，通过路由划分（`/` 与 `/admin`）。
- **样式**：推荐 Tailwind CSS 或等效原子化方案，便于实现响应式断点。
- **数据存储**：轻量方案（SQLite + ORM / 本地 JSON 文件）即可满足单人博客需求，优先保证简单可运行。
- **Markdown 渲染**：前端渲染（如 `marked` / `markdown-it` + 代码高亮）或服务端渲染均可，需注意 XSS 防护。
- **初始化数据**：提供种子脚本或默认管理员账号配置，并在 README 中说明默认账号及修改方式。
